Key features

Subagents

A subagent is an independent agent that Bob spawns for a focused, self-contained task. It works in its own context window and returns only a summary, which keeps your main conversation clean.

What you need to know

  • You approve the spawn: Bob asks for confirmation before a subagent starts.
  • Isolated context: A subagent does not see your conversation history unless Bob explicitly passes it in.
  • Used sparingly: Bob works directly by default and only uses a subagent for self-contained work that would add a lot of irrelevant content to the main context.
  • Mode limits: The active mode controls which subagent types Bob may spawn.

Subagent types

  • explore: Read-only codebase exploration on a lighter model. Best for searching, summarizing code, and finding files.
  • general: Full tool access on the default model. Best for any self-contained task that reads, writes, or runs commands.

Subagents vs. subtasks

  • Subagent: Runs in the background, is not interactive, and returns a summary.
  • Subtask: Appears in the UI with its own conversation, and you can follow and continue it.
  • Several parallel subagents are grouped into one collapsible panel that shows combined tool use, tokens, cost, and time.
