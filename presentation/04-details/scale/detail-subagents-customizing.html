Subagents

What they are

A subagent is an independent Bob AI agent with its own isolated context window. It handles a clearly scoped, self-contained task and returns only a compact summary back to the parent conversation — keeping the main context clean and focused.

  • Runs in complete isolation — no shared memory with the parent by default.
  • Two types: explore (read-only, lighter model) and general (full tool access, default model).
  • Set fork_context: true to pass the parent conversation history in when prior decisions matter.

How to use them

  • Decompose the work: Break large tasks into clearly bounded sub-tasks so each subagent concentrates on one thing.
  • Keep the main context lean: All intermediate steps happen inside the subagent — only the final summary comes back.
  • Pass only what is needed: Provide a compact description rather than the full history unless history is essential.
  • Enable subagents in modes: Add the subagent permission group to a custom mode's groups in .bob/custom_modes.yaml.

Trigger

  • Bob decides autonomously when to spawn one — you do not call subagents directly.
  • Bob only spawns a subagent when all three conditions are met: the task is self-contained, it would add significant irrelevant content to the main context, and it cannot be done in 1–2 direct tool calls.
  • You can auto-approve subagent spawning via the Subagent auto-approve setting (rated Low risk) to avoid being prompted each time.
  • Modes gate access — if the active mode does not include the subagent permission, Bob will not spawn one.
