Custom Modes

Custom modes extend Bob by creating specialized personas tailored to specific workflows. Each mode combines a role definition, custom instructions, and deterministic tool permissions to ensure consistent and controlled execution.

Configuration example & directory structure

.bob/custom_modes.yaml YAML 
customModes:
  - slug: docs-writer
    name: 📝 Documentation Writer
    description: Writes and revises docs.
    roleDefinition: >-
      You are a technical writer specializing in
      clear, accurate project documentation.
    whenToUse: Use for creating and updating docs.
    customInstructions: |-
      - Follow style guidelines strictly.
      - Ensure all code paths are valid.
    groups:
      - read
      - - edit
        - fileRegex: ".*\\.(md|mdx)$"
          description: Markdown only
      - skill

More info

Configuration files & scope

  • Workspace scope: Defined in .bob/custom_modes.yaml (available in the current project only).
  • Global scope: Defined in ~/.bob/settings/custom_modes.yaml (available across all workspaces).
  • Settings UI: Create and manage modes via Bob Settings → Modes tab → Add or Edit Project Modes.

Core properties (customModes)

  • slug (required) — Unique identifier (letters, digits, dashes: ^[a-zA-Z0-9-]+$). Also registers a /<slug> slash command.
  • name (required) — Display name shown in the UI mode picker.
  • roleDefinition (required) — Core persona and system prompt defining identity, expertise, and operational boundaries.
  • whenToUse (optional) — Tooltip guidance helping users and Bob select the right mode for the task.
  • description (optional) — Short summary of the mode's purpose.
  • customInstructions (optional) — Detailed behavioral guidelines appended to the system prompt.
  • groups (optional) — Tool permission groups. Must be listed explicitly; omitting groups grants no tool access.

Tool permission groups

  • read — Read files, directories, and code symbol lookups.
  • edit — Modify and create files. Can be restricted to specific file patterns using fileRegex (e.g. ".*\\.(md|txt)$").
  • execute — Run terminal and shell commands.
  • mcp — Access configured Model Context Protocol (MCP) servers and tools.
  • skill — Load and execute on-demand skills.
  • subagent, todo, workflow, mode — Subagent spawning, checklist tracking, workflows, and mode switching.

Mode-specific rules

  • Directory structure (preferred): Add rule files under .bob/rules-<mode-slug>/ (e.g. 01-guidelines.md), loaded alphabetically alongside customInstructions.
  • Single file: Add a .bobrules-<mode-slug> file in the workspace root.
  • Overriding defaults: Define a custom mode with the same slug as a built-in mode (e.g. ask, plan, agent) to override its default behavior.
