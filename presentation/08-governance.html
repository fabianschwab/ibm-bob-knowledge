Agent Governance

Proactive guardrails, policy enforcement, and permission scoping for AI agents.

A. Real-Time Policy Enforcement

Pre-execution lifecycle hooks evaluate actions before anything runs or reaches the model:

  • PreToolUse Intercepts and blocks tool calls or stop unauthorized commands
  • UserPromptSubmit Inspects user prompts and rejects policy violations before any LLM inference occurs.

B. Mode-Based Tool Permissions & Scoping

Granular restriction of agent capabilities based on active persona and task context:

  • Custom Modes Restrict tool group access per persona (e.g., Read-only vs. Edit vs. Command execution).
  • Mode Rules Scoped rule files define strict behavioral boundaries for specific agents.

C. Human-in-the-Loop Approval Controls

Explicit human supervision gates all state-changing or external operations:

  • Tool Approval Prompts Require manual confirmation or task-specific overrides before commands or file edits execute.
  • Editable Commands Developers can inspect and modify proposed shell commands directly in the approval UI before running.

D. Version-Controlled Guardrails

Shared, transparent policies versioned alongside your software delivery lifecycle:

  • AGENTS.md Project-level conventions, architecture constraints, and tech stack guidelines.
  • .bob/rules/ Team-wide standards version-controlled in Git, ensuring identical guardrails across all contributors.
Enterprise-Scale Governance & Centralized Control

E. Enterprise-Scale Centralized Enforcement

Tamper-proof policies managed centrally so individual users cannot tweak hooks, disable approvals, or bypass rules:

  • MDM & Read-Only Global Settings Global config managed via Intune/Jamf/Ansible; global hooks cannot be overridden or disabled by workspace settings.
  • Remote Zero-Trust Policy Engines HTTP PreToolUse/UserPromptSubmit hooks route decisions to centralized policy engines (e.g. Open Policy Agent) where logic cannot be inspected or altered locally.
  • CODEOWNERS & Protected Branches AGENTS.md changes in repositories strictly require security and architecture team approvals in PRs.
  • Enterprise AI Gateway & SIEM Central egress proxy enforces DLP, secret scanning, and automated audit streaming to Splunk/Datadog regardless of client state.
