Context Window Management — Context Hygiene

Use Subagents

Delegate repo-wide exploration to subagents (spawn_subagent). Only the condensed summary enters your main context window — the full working memory of the subagent stays isolated.

How subagents help with context

  • A subagent runs in its own isolated context window — all tool calls, file reads, and intermediate reasoning happen there.
  • Only the final summary is returned to the parent session, keeping your main window lean.
  • Ideal for tasks like "scan the entire codebase for usages of X" or "audit all API endpoints".

When to reach for a subagent

  • The task requires reading many files across the project that aren't directly relevant to your current conversation.
  • You need a broad exploration step before narrowing to a specific implementation.
  • You want to run parallel investigations without polluting the main transcript.

What stays in the main window

  • The subagent's summary — concise findings, not raw tool output.
  • Your original task description and any files you directly referenced.
  • Bob's subsequent reasoning and code changes based on the summary.
