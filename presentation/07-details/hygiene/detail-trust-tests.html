Context Window Management — Context Hygiene

Trust Tests Over Text

Keep AGENTS.md short and operational. When comments and code disagree, point Bob at runnable test suites rather than long chat debates — tests are verifiable ground truth that don't bloat the window.

The problem with long explanations

  • Lengthy AGENTS.md files and inline comment walls consume baseline overhead on every prompt.
  • Prose descriptions of "how the system works" can contradict actual code — Bob has no way to verify them.
  • Long chat debates about correctness generate transcript bloat without producing verifiable output.

Why tests are better context

  • A passing test suite is objective evidence — Bob can run it and observe the result directly.
  • Tests encode intent concisely: a 10-line test spec communicates more than a 200-line explanation.
  • Bob can iterate against tests without needing to hold the full architectural narrative in context.

Practical guidelines

  • Keep AGENTS.md focused on project conventions, commands, and constraints — not architecture lectures.
  • When Bob produces incorrect output, write or point to a failing test rather than re-explaining in chat.
  • Use short, focused rules files in .bob/rules/ instead of ever-growing inline instructions.
