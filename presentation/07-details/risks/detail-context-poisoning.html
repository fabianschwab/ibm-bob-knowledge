Context Window Management — Context Risks

Context Poisoning

When inaccurate or irrelevant data enters Messages (via bad log pastes or stale comments), Bob re-reads it on every turn and treats it as ground truth, causing reasoning drift and recurring tool errors.

How it happens

  • Pasting large, unfiltered log files that contain misleading or outdated state.
  • Leaving stale inline comments in files that contradict the current implementation.
  • Injecting test fixtures or mock data that Bob then reasons about as if it were production reality.

Why it is dangerous

  • The poisoned content is re-sent on every prompt — it never stops influencing responses until the conversation is cleared.
  • Bob cannot distinguish between reliable context and garbage input; it weights all Messages content equally.
  • Subtle drift compounds over turns: each hallucinated detail can seed the next response.

Mitigation

  • Use + to start a fresh task rather than continuing a contaminated conversation.
  • Reference specific file line ranges with @file.ts:10-30 instead of pasting raw output.
  • Remove or correct stale comments before asking Bob to reason about a file.
