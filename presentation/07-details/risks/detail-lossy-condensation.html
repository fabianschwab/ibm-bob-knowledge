Context Window Management — Context Risks

Lossy Condensation

When the context limit is hit, Bob automatically summarizes older conversation segments. Critical nuance, file snippets, or architectural decisions from earlier in the chat may be permanently dropped.

When it triggers

  • The conversation approaches the ~200,000-token limit of the context window.
  • Large file reads, command output, or extended back-and-forth exchanges fill the window rapidly.
  • Condensation is automatic and silent — there is no explicit warning before information is lost.

What gets lost

  • Precise file snippets shared early in the session that were not re-referenced later.
  • Architectural decisions or constraints discussed before the condensation threshold was reached.
  • Subtle clarifications or corrections that were added incrementally over many turns.

Mitigation

  • Start a new task with + when switching topics — this preserves project files on disk while resetting the message transcript.
  • Re-anchor important constraints early in each new session rather than assuming they persist.
  • Keep critical decisions in AGENTS.md or rule files so they are re-loaded from disk on every prompt.
