Context Window Management — Context Risks

Transcript Bloat

Large single dumps — such as entire multi-megabyte log files or full directory reads — consume token headroom rapidly, leaving less space for reasoning and driving up latency.

Common sources of bloat

  • Pasting complete log files or stack traces instead of the relevant excerpt.
  • Using broad @src folder mentions that inject thousands of lines at once.
  • Requesting full directory listings when only a handful of files are relevant.
  • Running commands that produce large stdout (e.g. npm install verbose output) without redirecting.

Why it matters

  • Every token consumed by raw data is a token not available for reasoning, planning, or tool output.
  • Bloat accelerates the onset of Lossy Condensation — Bob starts summarizing sooner.
  • Response latency increases because the model must process the full window on every turn.

Mitigation

  • Use targeted @file.ts:45-67 line-range mentions instead of whole-file or whole-folder references.
  • Add context incrementally — start with a minimal reference and expand only if Bob needs more detail.
  • Prefer structured summaries (e.g. grep output, symbol overviews) over raw file dumps.
